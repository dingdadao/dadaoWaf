>
> 最后更新：2026-10-22

## 总览

| 状态 | 数量 | 说明 |

| ✅ 已实现 | 32 项 | 可用，有测试覆盖 |

## 二、部分实现（9 项）

| 功能 | 现状 | 缺什么 |

## 四、建议顺序

按「投入产出比」排：

| 顺序 | 功能 | 理由 |
|---|---|---|
| 1 | **CC 防护** | 现在被打就是硬扛，最基础的防护缺失 |
| 2 | **应用级策略** | 结构已有，接上就行，让不同应用能独立配置 |
| 3 | **人机验证** | `challenge` 动作现在是假的，要么做完要么删掉 |
| 4 | **登录页** | 控制台现在无认证，只能靠回环地址保护 |
| 5 | **攻防地图 + 统计** | 概览页现在只有数字，缺可视化 |
| 6 | **ACME** | 证书续期是真实痛点 |
| 7 | **规则包订阅** | 规则能自动更新，不用跟着版本走 |

前 4 项约 8 人日，做完产品就「能用」了。

## 五、和雷池的差距

| 维度 | 雷池 | HomeWAF |
|---|---|---|
| 检测方式 | 语义分析 + 规则 | 纯规则（41 条） |
| 规则更新 | 官方规则包自动更新 | 跟版本走 |
| CC 防护 | 完整 | 无 |
| Bot 防护 | JA4 指纹 + 人机验证 | 无 |
| 证书 | 内置 Let's Encrypt | 手动 |
| 概览 | 攻防地图 + 趋势 | 6 个数字 |
| 部署 | Docker 一键 | 单二进制 |
| 资源占用 | 较重（语义分析模型） | 轻（41 条正则） |

**我们的优势**：单二进制、无依赖、资源占用低、配置在数据库里可控。
**我们的劣势**：检测能力弱、缺 CC/Bot 防护、运维功能少。
