# 产品功能设计

> 本文档定义 HomeWAF 的完整功能形态，作为后续迭代的依据。
> 功能参考雷池（SafeLine），但按家用场景做取舍——去掉企业级复杂度，保留真正用得上的能力。
>
> 最后更新：2026-10-22

## 1. 产品定位

**一句话**：装在家里的反向代理 + WAF，保护内网服务不被公网扫描器骚扰，同时让自建服务能用 HTTPS 域名访问。

**和雷池的差异**：

| 维度 | 雷池 | HomeWAF |
|---|---|---|
| 目标用户 | 中小企业运维 | 家庭用户 / 极客 |
| 部署 | Docker 多容器 | 单二进制 |
| 资源 | 2 核 2G 起 | 树莓派级 |
| 配置方式 | 数据库 + 控制台 | 数据库 + 控制台（无配置文件） |
| 检测 | 语义分析模型 | 规则 + 预过滤 |

**核心取舍**：放弃「企业级完备」，换取「装完就能用」。

## 3. 模块设计

### 3.1 概览

**目标**：一眼看出「现在有没有被打」。

**布局**（参考雷池）：

```
┌──────────────────────────────────────────────────┐
│ 今日请求 12,483   拦截 342   封禁 8   应用 3      │
├──────────────────────────┬───────────────────────┤
│                          │  攻击类型分布          │
│      攻防地图             │  ▓▓▓▓▓▓ SQL 注入 45%  │
│   （世界地图 + 攻击弧线）  │  ▓▓▓▓ 扫描器 28%      │
│                          │  ▓▓ XSS 15%           │
│                          │  ▓ 其他 12%           │
├──────────────────────────┴───────────────────────┤
│  24 小时请求 / 拦截趋势（双线图）                  │
├──────────────────────────────────────────────────┤
│  最近攻击（时间、来源、类型、处置）                │
└──────────────────────────────────────────────────┘
```

**攻防地图设计**：

- 底图：世界地图（简化轮廓，SVG）
- 攻击来源：按 IP 归属地打点，用 GeoIP 数据库
- 攻击弧线：从来源点连到本机位置，带流动动画
- 颜色：SQL 注入红、XSS 橙、扫描器灰
- 无 GeoIP 数据时：显示「未启用地理位置」提示，不报错

**技术选型**：
- 地图：内嵌简化 SVG（不引第三方地图库，避免体积）
- 数据：GeoIP 用 `maxminddb` + 离线库（GeoLite2 City，约 60MB）
- 可选：不装 GeoIP 库时地图区域显示占位

**数据来源**：`events` 表按时间聚合，不需要新表。

### 3.2 防护应用

**字段**（和雷池一致）：

| 字段 | 必填 | 说明 |
|---|---|---|
| 名称 | 是 | 显示用 |
| 对外域名 | 是 | 单个域名 |
| 监听端口 | 否 | `80, 443`，留空任意 |
| 上游服务器 | 是 | URL，可多个 |
| SSL | 否 | 开关 + 证书选择 |
| 防护策略 | 否 | 覆盖全局策略 |

**路由规则**（高级）：

```yaml
routes:
  - path: /api
    upstream: http://192.168.1.5:8080
    rewrite: { mode: prefix, value: /v1 }
  - path: /static
    upstream: http://192.168.1.5:80
```

**策略覆盖字段**（应用与路由都可配，路由优先，逐字段合并）：

| 字段 | 说明 |
|---|---|
| `preset` | `lenient` / `balanced` / `strict` |
| `protection` | 17 类攻击的 off / monitor / block |
| `observe_mode` | 只记录不拦截 |
| `block_threshold` | 拦截分数 |
| `ratelimit` | 整份替换全局限流配置（需显式 `enabled: true`） |
| `require_challenge` | 强制人机验证 |
| `allow_cidr` / `deny_cidr` | 应用级 CIDR |
| `max_body_size` | 请求体检测上限 |
| `allow_methods` | HTTP 方法白名单 |

**健康状态**：列表里显示每个上游的在线/离线，来自主动健康检查。

### 3.3 攻击事件

**列表列**：时间、来源 IP、归属地、攻击类型、命中规则、处置、应用。

**详情页**：
- 完整请求（方法、路径、Header、Body 摘要）
- 命中的规则列表（规则名、匹配片段、分数）
- 处置链路（ACL → 检测 → 封禁）
- 关联日志（同一个请求 ID 的所有日志）

**筛选**：时间范围、攻击类型、应用、来源 IP、处置动作。

### 3.4 黑白名单

**三类规则**：

| 类型 | 说明 |
|---|---|
| IP 规则 | CIDR 网段，allow / deny |
| 自定义规则 | 匹配路径 / UA / Header，执行 allow / deny / log |
| 订阅源 | 外部 IP 库，带防投毒护栏 |

**优先级**：白名单 > 黑名单 > 自定义规则 > 内网策略 > 检测。

### 3.5 CC 防护

**三层限流**：

| 层级 | 配置 | 说明 |
|---|---|---|
| 全局 | `global_qps` | 整机总 QPS 上限 |
| 单 IP | `per_ip_qps` / `per_ip_conn` | 单 IP 频率与并发 |
| URL 级 | `per_url_qps` | 单个路径的 QPS |

**超限处置**：`block` / `challenge` / `log`，可配。

**实现要点**：
- 1 秒滑动窗口（当前窗口 + 上一窗口加权，避免固定窗口临界突刺）
- 16 个分片计数器，定期清理过期键；被拒绝的请求不延长封禁窗口
- URL 级 key 为 `应用 + 规范化路径`，只在开启 URL 限流时分配
- ACL 明确放行的 IP 不参与限流
- 默认关闭，避免升级后影响内网大流量下载 / 同步

### 3.6 Bot 防护

**人机验证**：

```
首次请求 → 返回 JS 挑战页 → 浏览器计算 → 带 token 重试 → 放行
```

- 挑战页：内联 JS SHA-256 工作量证明，不依赖第三方；纯 HTTP 环境也可用
- token：HMAC-SHA256 签名，绑定应用、客户端 IP 与过期时间；通过后写入同签名 Cookie
- 难度：前导零十六进制位数（默认 4），每 +1 计算量约翻 16 倍
- 触发条件：路由 `require_challenge`、CC 超限且动作配为 `challenge`
- 已通过验证的请求仍受硬限流约束（验证只证明「不是脚本」，不等于无限配额）

**UA 指纹**：识别常见扫描器 / 爬虫库，可选放行搜索引擎。

### 3.7 防护配置

**攻击类型开关**：17 类，三态（off / monitor / block）。

**灵敏度档位**：宽松 / 平衡 / 严格，一键调整阈值。

**观察模式**：只记录不拦截，带自动关闭时间。

**自动封禁**：触发分数、封禁时长档位、IPv6 聚合前缀。

**检测白名单**：按应用 / 路径 / 规则豁免，用于处理误报。

### 3.8 日志

四类日志，按天分文件，异步写入，支持按请求 ID 串联。

**控制台展示**：表格式，按类型显示不同列，点击展开原始 JSON。

### 3.9 系统设置

| 分组 | 内容 |
|---|---|
| 管理面 | 监听地址、认证方式（token / 账号密码） |
| 真实 IP | 可信代理、头部优先级 |
| 证书 | 全局证书、ACME 配置 |
| 告警 | 邮件 / Webhook / 企业微信 |
| 数据 | 备份、清理策略 |

## 4. UI 设计规范

### 4.1 布局

左侧固定侧边栏（196px）+ 右侧内容区，顶部状态条 52px。

**为什么不用顶部导航**：菜单项有 9 个，顶部放不下；侧边栏能一直可见，切换快。

### 4.2 配色

| 用途 | 浅色 | 说明 |
|---|---|---|
| 背景 | `#f7f7f5` | 暖灰，不刺眼 |
| 卡片 | `#ffffff` | |
| 边框 | `#e5e4df` | |
| 主色 | `#185fa5` | 蓝，用于主按钮和链接 |
| 危险 | `#a32d2d` | 红，用于拒绝/封禁 |
| 成功 | `#0f6e56` | 绿，用于放行/正常 |
| 警告 | `#854f0b` | 橙，用于观察/记录 |

**状态色约定**（全站统一）：
- 2xx 绿、3xx 蓝、4xx 橙、5xx 红
- 放行绿、拒绝红、观察橙

### 4.3 组件规范

| 组件 | 规范 |
|---|---|
| 卡片 | 白底、1px 边框、8px 圆角、无阴影 |
| 表格 | 表头浅灰底、行高 36px、hover 浅色 |
| 按钮 | 主按钮实心蓝、次按钮描边、危险操作红字 |
| 表单 | 标签在上、输入框 6px 圆角、错误红字 |
| 空状态 | 居中灰字 + 一句行动建议 |

### 4.4 交互原则

1. **改动立即生效**，不需要「应用」按钮
2. **失败不清空表单**，用户能直接改
3. **危险操作二次确认**，确认文案说清后果
4. **空状态给建议**，不是只写「暂无数据」

## 6. 不做的功能

明确排除，避免范围蔓延：

| 功能 | 原因 |
|---|---|
| 集群模式 | 家用单机，无此需求 |
| 多租户 | 同上 |
| 合规报表 | 家用不需要等保 |
| 插件系统 | 复杂度远超收益 |
| 移动 App | 网页够用 |
